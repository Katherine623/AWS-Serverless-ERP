# Agent 修復與變更管理政策

## 人工核准

所有可能改變 AWS 狀態的動作都必須先產生計畫，內容至少包含目標資源、原始證據、預期結果、
回復方式與驗證步驟。Agent 在沒有有效核准紀錄時只能執行 List、Get、Describe 類唯讀 API。
刪除 EBS、釋放 Elastic IP 與修改 IAM Policy 一律視為高風險變更。

## 白名單修復

自動化執行器只能接受明確定義的動作與結構化參數，禁止執行 Agent 自由產生的 Shell 指令。
第一階段白名單可包含設定 Log Group 保存期限、完整啟用 S3 Block Public Access，以及移除
特定 Security Group 公開規則。每次執行必須保存操作者、核准時間、輸入參數與 AWS 回應。

## 修復後驗證

變更完成不代表事故結束。系統必須重新收集目標資源狀態並執行原始規則；只有 Finding 消失且
合法存取測試通過才可標記為 resolved。若驗證失敗，工作流程應停止其他變更並通知人工處理。
